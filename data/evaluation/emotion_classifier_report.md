# Phase 7 optional trained emotion classifier — evaluation report

Generated by `objective_evaluation.train_emotion_classifier` +
`objective_evaluation.evaluate_emotion_classifier`. objectives.md Phase 7 is
explicitly optional and its own acceptance criteria permit *not* adopting
the trained model — this is a real experiment with a real, honestly
reported outcome, not something tuned toward a predetermined "success."

## What was trained

A scikit-learn `LogisticRegression` (`class_weight="balanced"`) over:
- the rule baseline's own per-category evidence distribution
  (`EmotionAnnotation.distribution`), valence, arousal — features the
  rule engine (`preprocess/emotion.py`) already computes, reused rather
  than re-derived;
- a negation flag and one-hot sentence type;
- word 1-2gram TF-IDF (max 1,500 features) over the raw text.

Per objectives.md's own guidance ("do not train a language model from
scratch"; classical classifiers preferred unless the dataset is large
enough for a transformer) — not a compact-transformer fine-tune, since
even after eval-set scaling the trainable pool here is far below what
that would need.

## Training-pool construction

Started from `data/external/redv2_sample.json`'s full 354-row filtered
REDv2 candidate pool and excluded every text already present anywhere in
`data/evaluation/dev.jsonl`/`test.jsonl` — not just `test.jsonl` — so this
report's numbers are a genuine held-out comparison. This shrinks the
trainable pool to **168 examples**, stratified 80/20 into 135 train / 33
dev per label.

**A real, honest cost of this design**: eval-set scaling's own REDv2
sampling (`data/evaluation/README.md`'s Tier 2, up to 30 examples/label)
had already consumed nearly the entire "surprise" candidate pool (28 total
candidates existed), leaving **zero** surprise examples to train on.
`surprise` was dropped from the classifier's label set rather than trained
on nothing — reported here, not hidden. The other 5 labels had enough
(10-57 per label) to train on.

## Results (33 held-out examples, never used in training)

| | rule baseline | trained classifier |
|---|---|---|
| macro F1 | 0.190 | **0.428** |
| angry F1 | 0.000 | 0.400 |
| fear F1 | 0.000 | 0.000 |
| happy F1 | 0.769 | 0.769 |
| neutral F1 | 0.000 | 0.417 |
| sad F1 | 0.182 | 0.556 |

- **Improvement: +0.238 macro F1** — clears the "must outperform the rule
  baseline" bar by a real margin at this sample size, not noise.
- **Brier score (multiclass, calibration): 0.664** — poor. For 5 classes,
  uniform random probability guessing scores ~0.8 on this metric, so 0.664
  is only modestly better than "the model doesn't really know" — its
  predicted probabilities aren't trustworthy even where its top-1 answer
  is often right.
- **Inference: 0.01 ms/example** — trivially fast locally; latency was
  never going to be the blocker.

## Decision: NOT ADOPTED

Per objectives.md's own explicit permission ("the model must not be
adopted if improvement is negligible or confidence is poorly
calibrated"): macro F1 improvement is real and non-negligible, but
calibration is poor, and the held-out sample (n=33, one label dropped
entirely) is small enough that a single-number "yes/no" here shouldn't be
treated as final. **Not wired into `PreprocessPipeline`.** The trained
model artifact and its exact held-out split are preserved at
`.cache/models/emotion_classifier/` (gitignored — see `objective_evaluation.train_emotion_classifier`
for regenerating) if this is revisited once the evaluation set grows
further and a real REDv2 reserve exists for both eval-set scaling and
classifier training without one starving the other.

## What would change this decision

- A larger, disjoint REDv2 reserve set aside specifically for Phase 7
  before Tier 2 sampling runs, so classifier training isn't competing with
  eval-set scaling for the same limited candidate pool (this is the root
  cause of the `surprise` gap above).
- Calibration-specific fixes (Platt scaling / isotonic regression via
  `CalibratedClassifierCV`) before re-measuring Brier score — not
  attempted here since the underlying pool is already this small;
  recalibrating on an even smaller held-out split risks overfitting the
  calibration itself.
